# 050 — CI, lint for bugs, and the release check

**Type:** chore · **Priority:** P2 · **Status:** Done

## Goal
Tests that run on every push without anyone remembering to; a linter that finds bugs without imposing a style; and a release check that tests the deployed site once it really runs the new commit.

## Decisions (agreed with the user, 2026-10-22)
- **CI reports, it doesn't block:** a GitHub Actions workflow on every push, with no commit hook and no branch protection.
- **Lint for bugs, not style:** ruff with pyflakes and bugbear only (`select = ["F", "B"]`), with B008 off (FastAPI's `Depends(...)`). No style rules, no formatter. A deliberate exception gets `# noqa: <rule>`.
- **JS:** `node --check` on each module. No ESLint for now.
- **`/healthz` reports the deployed commit** (Render's `RENDER_GIT_COMMIT`). The release check polls it before running the browser tests against the site, instead of waiting a fixed time.

## Notes
- Implemented 2026-10-22: `.github/workflows/tests.yml`, `[tool.ruff.lint]` in `pyproject.toml`, `scripts/release_check.py`.
- First run green: 127 unit and 73 browser tests in headless Chrome on `ubuntu-latest`, about 1.5 minutes. Uses `actions/checkout@v5` and `astral-sh/setup-uv@v7` (Node 24).

  - Unused loop variables and an unused import, empty f-strings, and an exception re-raised `from` its cause.
- A docs-only push on 2026-10-22 failed its UAT run once with the fixed wait (tests ran during Render's swap) and passed on rerun; that prompted the commit check.
