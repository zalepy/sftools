# sftools
tools for satisfactory

Current operation:
* Data scraping: Scripts under `craw` are used to scrape data from [Satisfactory-Calculator](https://satisfactory-calculator.com). See [craw/README.md](file:///d:/gits/sftools/craw/README.md) for details on how to run them and what they do.
* setup root demand in `sftools_service.logic.demand_calculator`
  ```
    root_demand_item = items['Smart Plating']
    root_demand = {'Smart Plating': Demand(name='Smart Plating', item=root_demand_item, rate=2.0, _type=DemandType.PRODUCE)}
  ```
    where `items` is loaded from the json stored in the `data` directory

Output:
Each step of the calculation generates lists of objects of two types:
- ProductionNode - describes production required to fulfil the need of specific item
- Demand - demand generated by the production node

 
Notes on calculation:
* buildings needed to satisfy the demand are shown as `float`
* number of buildings is rounded up before processing sub demands
* aggregation of production nodes, and pending demand is done after each step,
  however demand that occurs on separate layers/iterations will be rounded up
  individually


To start web server execute:
`waitress-serve --port=8000 "sftools_service.main:app"`

Plans and Features:
* **Graph Visualization**: High-performance SVG/Cytoscape chart representation of the production chain. (Done)
* **Interactive Adjustments**: Users can override the scale (number of buildings) for any node in the graph. These changes automatically propagate through the dependency chain. (Done)
* **Recalculation Mode**: Unlike the initial construction which uses a BFS expansion, the "recalculate" mode operates on the preexisting graph, preserving topological links while adjusting throughput. (Done)
* **Lines and Logistics**: Future plans include representing physical lines and considering splitting/merging limitations.


## Web Interface

To run the web interface locally:

1. Install requirements:
   ```bash
   pip install -r requirements.txt
   ```
2. Run the server:
   ```bash
   uvicorn main:app --reload
   ```
3. Open http://127.0.0.1:8000 in your browser.


## Deployment on Render

This application is ready for deployment on [Render](https://render.com/).

1. Create a new **Web Service**.
2. Connect your repository.
3. Use the following settings:
    - **Runtime**: Python 3
    - **Build Command**: `pip install -r requirements.txt`
    - **Start Command**: `uvicorn main:app --host 0.0.0.0 --port $PORT`


## Testing

### Manual Execution
To run unit tests manually, use `pytest` from the root directory:
```bash
# Using venv python directly (recommended)
.venv\Scripts\python -m pytest

# OR if you have poetry installed and configured
poetry run pytest
```

### Antigravity Integration
You can ask Antigravity to run tests for you by simply requesting "Run tests". It will execute the pytest command in the terminal.

### Pre-push Checks
To ensure tests pass before pushing to GitHub, you can use a git `pre-push` hook.
1. Create a file `.git/hooks/pre-push` (no extension) with the following content:
   ```bash
   #!/bin/sh
   echo "Running tests..."
   # Adjust path to your python executable or use 'pytest' if in PATH
   ./.venv/Scripts/python -m pytest
   if [ $? -ne 0 ]; then
       echo "Tests failed! Push aborted."
       exit 1
   fi
   ```
2. Make it executable (if on Linux/Mac, `chmod +x .git/hooks/pre-push`). Windows Git Bash usually handles this, or you can verify it via `ls -l .git/hooks/pre-push`.
